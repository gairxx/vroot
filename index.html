# Built for agents

Agents do not need a nicer terminal — they need resources on demand and no coordination overhead. No daemon, no registry, no sudo, tens of milliseconds to a root shell.

Machine-readable

$ vroot build -python --json
{"env":"…/python-84d0423ed3.sqfs","cached":false}

$ vroot ls --json
[{"name":"job7","env":"python-84d0423ed3",
  "bytes":20598,"age_minutes":3}]

stdout is pure JSON, logs stay on stderr, exit codes are forwarded from the command you run.

Parallel-safe

$ vroot build -python &
$ vroot build -python &
{"env":"…","cached":false}
{"env":"…","cached":true}

One image per flag set: the first agent builds, the rest wait on a lock and reuse it. Cache extraction is atomic, so concurrent launches cannot corrupt each other.

Checkpoint and fork

$ vroot save golden golden.vroot
$ vroot golden.vroot try1 -- pytest -q
$ vroot golden.vroot try2 -- pytest -q
$ vroot try1 -- git diff

The image is read-only; every fork writes to its own overlay, so a failed attempt costs a name, never the good state.

Host stays hidden

Real uid 0 inside, but no host filesystem, no host processes and no host network surprises unless you mount or allow them. -offline cuts the network, anonymous sandboxes vanish on exit, named ones persist until vroot rm.

# Quick start

vroot                      # banner + quick-start help
vroot -base                # a root shell (blank Alpine Linux)
vroot -python              # a root shell that has Python
vroot -node -python        # compose flags freely
vroot -sqlite -python db   # a persistent sandbox named "db"
vroot -rust -- cargo build # run one command instead of opening a shell
$ vroot -python -- sh -c 'id; hostname; ls /home'
uid=0(root) gid=0(root)
vroot
ls: /home: No such file or directory   ← the host is not visible

# How it works

1

Resolve flags

Each flag maps to a small recipe. -php -sqlite -git merges into one environment definition.

2

Build once to a file

A minimal Alpine (or Debian) rootfs is populated in a sandbox and packed into a single squashfs image.

3

Launch copy-on-write

The image is mounted with overlayfs and started via bubblewrap: real root, isolated namespaces, your host hidden.

# Install

$ curl -fsSL https://raw.githubusercontent.com/gairxx/vroot/main/install.sh | sh

Then check the host and start a shell:

vroot doctor      # verify bubblewrap, namespaces, squashfs
vroot -python     # a root shell with Python
MethodCommand
Clone and installgit clone https://github.com/gairxx/vroot.git && cd vroot && sh install.sh
Source archivemain.tar.gz → unpack → sh install.sh
Custom prefixcurl -fsSL …/install.sh | sh -s -- --prefix /opt/vroot
Pin a refcurl -fsSL …/install.sh | sh -s -- --version <branch-or-tag>
Uninstallcurl -fsSL …/install.sh | sh -s -- --uninstall

Requires Linux with user namespaces, plus bubblewrap, util-linux and squashfs-tools. docker is only needed for flags that build on a Debian base. The installer needs no build step and keeps sandboxes/images when uninstalling.
